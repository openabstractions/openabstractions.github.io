Definition: abstraction.storage.loan

Borrowing · Types · Fields · Enumerations · Constants · Encoding · Refusals

Service Borrowing [DEF-S1]

Model loans served by the residency provider (oa:residency). The provider listens on the shared identity-bound transport and admits programs of its own account that hold abstraction.storage/borrow; a call whose peer identity could not be obtained fails with caller_unavailable, insufficient program proof with identity_required. No application receives a handle.

Wire identity: abstraction.storage/loan@1

Handler error codes, declared by loan_error_codes: caller_unavailable, identity_required. Generated bindings name each as a ServiceErrorCode member beside the dispatcher's own codes.

Frames carry version, service, method and typed arguments. Transport owns framing, associated exchanges, deadlines and connections. Unknown version/service/method and malformed arguments are rejected before invoking a handler. One-way WriteFrame success means local submission, not remote acceptance or persistence.

Request-response methods use ExchangeFrame. Replies carry version, service, method, ok and payload; success payload contains typed value (or an empty object for void). Error payload contains nonempty code and message, which may be empty. ServiceError preserves unknown codes. Unexpected handler failures become handler_error without private details; invalid results become invalid_result. Clients validate reply identity and result before exposing it. A malformed frame or transport failure remains a local error; the transport must associate each response with its exchange. C++ dispatchers are pure protocol bindings, not listening servers.

Lend the model named by its storage manifest id to an engine the caller is about to launch, named by launch in the caller's own words. accepts lists the deliveries the engine takes, in order of preference; devices lists the device handle types it imports, for a device delivery. The lender fills or reuses one holding of the model and answers a Loan whose parts each use the first accepted delivery the lender can make, or no_acceptable_delivery. Gated by abstraction.storage/borrow on resource model:<manifest id>, granted by default only to registered engine-provider programs. A model the lender's stores do not hold is unknown_model; busy is a holding being filled for another borrower past the caller's deadline.

Borrow

request-response BorrowResult

  • Argument 1: string model (required; length 71..71 UTF-8 bytes; pattern ascii_lower_token; refusal bad_value, including zero/false/empty)
  • Argument 2: string launch (required; length 1..128 UTF-8 bytes; pattern no_control; refusal bad_value, including zero/false/empty)
  • Argument 3: list<Delivery> accepts (required; length 1..4 entries; refusal bad_value, including zero/false/empty)
  • Argument 4: list<DeviceHandle> devices (required; length ..7 entries; refusal bad_value, including zero/false/empty)
  • Argument 5: string resource_lease (required; length ..128 UTF-8 bytes; pattern no_control; refusal bad_value, including zero/false/empty)

End a loan before its engine releases it: the lender closes its end of the lease and drops the ledger row. A loan also ends when the engine closes its lease end, by release or by exit. Only the borrowing program may return its loan.

Return

request-response ReturnResult

  • Argument 1: string loan (required; length 1..64 UTF-8 bytes; pattern ascii_name; refusal bad_value, including zero/false/empty)

The caller's loans in force. limit is 1..64. Continuations are at most 256 bytes and name a retained page position; an unknown one is invalid.

Enumerations [DEF-T5]

Enum fields carry JSON strings containing exact member wire spellings, never numeric IDs. Unknown names are preserved with grant and refused as bad_enum with refuse on read and write. Optional absent fields preserve presence separately from an empty string.

An enumeration is a closed vocabulary of wire names, and each one says on its own what a reader does with a member it has never heard of [DEF-A5].
