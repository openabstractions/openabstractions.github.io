Catalogue

Fifteen abstractions with separate responsibilities

Software uses abstractions to span operating systems and libraries. OA carries the same idea into capabilities supplied by local programs, operating-system facilities, and remote services. Choose the smallest abstraction your application or provider needs. Open the technical detail for contracts, clients, source publication and recorded language results.

Repository presence and a source build are separate from installed readiness. Current coverage carries the reviewed verdicts.

Pause a specific action and ask the responsible person for a decision.

Safe shared updates

abstraction-cas · Public source

Runtime configuration

Named credentials

Verified downloads

abstraction-download · Public source

Application entry point

Resolve a capability through one local OA service while providers and service locations can change.

abstraction-facade · Public source

Caller identity

abstraction-identity · Public source

Model inference

Stream chat, embeddings, speech, transcription, live sessions and images through an OA-selected provider.

abstraction-inference · Public source

Durable jobs

Submit work once, save its identity and observe, cancel or recover the same accepted work.

abstraction-job · Public source

Structured events

abstraction-logging · Public source

Model lookup
