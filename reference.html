Developer reference

Find a capability, contract, or method

This page is for developers integrating a capability; people who use applications find the install steps on the Adopt page.

Open Abstractions gives applications stable capability APIs above operating systems, local engines, and remote services. This page defines the shared vocabulary, shows the service lifecycle, and indexes the current APIs.

Runtime release: 0.3.0. See the release evidence and limits. Capability SDKs have independent versions. Match package availability and installation evidence to the API you adopt.

Shared vocabulary

Terms used across capabilities

Abstraction
A stable concept and API whose meaning holds across operating systems, libraries, engines, and service providers. Each abstraction can be adopted independently.
Capability
The work an application asks OA to supply, such as reading content, submitting durable work, routing a model, or asking a user a question. One or more modules implement a capability as a service.
Module
One repository under openabstractions-flat/abstraction-*, stacked so a higher module builds on a lower one's guarantees, such as the model module resolving a reference before the download module moves bytes.
Service
A named wire interface and behavioral version, such as abstraction.logging/sink@1, and the endpoint inside the runtime that answers its calls — one word for the interface and the thing that answers it, as gRPC uses it. Distinct from a contract, the numbered rule set that defines its promises and limits. In the module catalogue, service is the Kind a module's definition earns by declaring a service that is not direct.
Provider
An implementation behind a capability contract, such as the download module's transfer agent or the local-stores module's read-only indexer of what a machine already holds. In the module catalogue, provider is also a Kind value: a module named <x>-over-<y> with a command, or one whose definition declares guarantees and no service.
Runtime
The installed OA program selected for the connected local account and program. It resolves capabilities, enforces rights, owns service state, and mediates providers. It is one program, openabstractions serve runtime: installed, the platform's service manager starts it as the background service; run directly, the same command starts it in the foreground. On Windows the per-user supervisor, openabstractions serve supervisor, starts it and restarts it after a failure.
Facade
The shared entry point used to resolve typed capability clients. Machine selects and trusts the local runtime; Resolve… methods return a bound client.
Contract page
A module's CONTRACT.md: the document stating a contract's obligations, admission order and refusal reasons. Its rule ids, such as INF-A1, are what tests and refusals cite.
Requirements
The guarantees and execution placement requested during resolution. The runtime returns an eligible binding or a typed refusal.
Guarantees
Contract-specific promises required before work starts, such as recovery across caller exit. Accepted work keeps the guarantees under which it was admitted.
Placement
Requested execution location during resolution: local, remote, or any where the capability supports it; the resolved endpoint has a fixed placement.
Subject
The account-plus-program a decision, or a job's ownership, is about. A job's subject observes, lists, reads and cancels what it submitted, with no rule consulted for that; rights and identity read the same subject when deciding or verifying a peer.
Binding
The resolved client-to-service tie: in the facade, the capability, service, provider revision, transport, endpoint, placement, and guarantees a continuation call validates against. Identity's peer answer (Bind/BindConn) takes once at accept and freezes, refusing a later re-derivation.
Idempotency key
A stable caller-owned key created before submission; a retry with the same key reconciles the same job instead of starting a new one.
Job
The module that gives submitted work a durable identity, acceptance, reconciliation, cancellation, and inventory: abstraction-job. Other capabilities submit through it rather than each tracking accepted work of their own. An accepted job is work a service owns; its receipt records the job identifier, logical owner, idempotency key, binding, and accepted guarantees.
Peer identity
Operating-system evidence about the connected account, process, executable, package, and code identity. Each attribute carries its proof strength.
Rights
Policy decisions for an action on a resource by a verified peer. The service that owns the resource enforces the decision.
Budget
A credential's daily spend cap, checked before a hosted call starts. A request over an exhausted budget refuses budget_exceeded.
Ceiling
The strongest proof identity can bind for an attribute.
Application manifest
An operator-installed record naming an application, its executable, display title, start guidance and optional activation recipe. A running instance announces its interfaces separately.
Application instance
A leased OA handle returned when a ready application announces itself. Renewals keep that exact instance present until withdrawal or expiry.
Application context
An application-owned document or workflow name, title, and revision. Interaction adapters use the revision to reject a call aimed at an older target.
MCP gateway
An authorized integration program that exposes a curated set of OA-backed tools to a Model Context Protocol client. Its operating-system identity determines its OA rights.
Work
What a person or application wants OA to do, before it is submitted: the plain word for the thing a job accepts and records.
Store
Where a provider keeps content. OA storage offers content-addressed objects and a combined inventory of available stores. Its local-stores provider can discover model files managed by other applications. Writes to OA-managed content use content-writer@1.
State file
The CAS state file: the lock-guarded shared state abstraction-cas maintains.
Share
A shared folder on a NAS.
Handle
An open read handle in storage, such as a POSIX file handle or a Windows HANDLE.
Sink
A destination for structured log records, exposed through abstraction.logging/sink@1. Default handlers resolve an OA logging service and report resolution failures. After a service outage, they retry with a bounded queue and report dropped records. Local fallback requires explicit provider selection.
Destination
Where a download writes bytes: a plain path outside the content store, named by the caller for a deprecated in-process download (download.Open()/Get()) and by the runtime for a job-service download, to its own result document. It never names the store.
Family
The canonical identity two names for the same weights must agree on before one of them can answer for the other, resolved by the model module. The router reads a family as the cluster of a model server's own aliases resolved to that identity, together with which servers and stores hold each one.
Lease
One axis, two senses. A resource lease (abstraction.resource/leases@1) is asked back with a deadline, renewed while the holder keeps using it, and given back when the holder yields. A job's lease is exclusive, carries an epoch, and is never asked back; job states it with the job (JOB-L1).
Yield
Giving a resource back on the service's request: a lease holder yields through Answer; an attached holder yields through its server's own unload. What the instrument shows afterwards is the answer. An engine's own eviction is not a yield.
Resident
Loaded and currently answering calls, said of a model a model server or a model host provider is holding in memory under a lease.
Model server
A declared model runtime or provider endpoint this machine or an operator names — Ollama, LM Studio, Lemonade, or a hosted server such as OpenRouter. Registered through inference server add (inference host add until the next release) and addressed by a rights rule as host:<name> (renamed to server:<name> on the wire in a later release). abstraction-provider-modelhost's own process, which loads a model file into an engine and keeps it resident, is declared to the runtime the same way, as host:modelhost.
Host
The address part of a URL: the machine a transport connects to, as in OLLAMA_HOST or a --host flag. Distinct from a model server.
Claimed
An unverified, self-reported assertion, with no verification behind it: a peer attribute the peer itself asserted (identity's lowest proof level), a log hop the writer itself asserted (its lowest attestation standing), or a resource-table row an engine or its adapter self-reported (with no instrument behind the amount).
Location
One location in config's precedence ladder — machine, user, or process — ordered nearest first; the nearer location's value wins, and every answer carries the location it came from.
Resource
A named target for rights and for the resource module alike: credential:<name> or account as a rights target; card:<n> for an accelerator's memory (cuda:0 on CUDA, a DirectML adapter, or DRM card0), memory for system memory, or awake, the pool a wake lease claims, as one of the machine's scarce pools.
Holder
The program holding a lease or a resource amount.
Hold
One row of the resource table: an account, a program, a resource, and an amount, whether measured or claimed. A holder in two processes is two holds.
Credential manager
The abstraction.credentials/manager@1 service that registers, rotates, revokes, lists, and audits named secrets.
Operator
A person acting at the command line or the Panel, distinct from an application. Also the generated *Operator services (abstraction.rights/operator@1, abstraction.asks/operator@1, and others) that such a person, or a program the installation trusts as one, reaches through an explicitly authorized typed-peer callback.
Deprecated
A still-shipped earlier interface, each kept with its removal release named, or without one until then. The embedded file-reading config provider (Go config.go, Python python/abstraction_config.py) is kept for a deliberate out-of-tree adopter that reads configuration files directly instead of the service; Load, Watch, and JobStore are its deprecated names. Job's file-backed record interface (Store, shipped as NewFileStore) is deprecated the same way.
Inference gateway
A loopback OpenAI- and Anthropic-shaped listener on the runtime, for a program that only knows a base URL and an API key. It stays off by default; an issued gateway key binds one program.
Gateway key
The key the inference gateway issues to one program so it can reach the runtime through the gateway. A hosted server's own credential is instead called an API key.
Alias
A model's name as a model server reports it. Used as a family's identity when no store descriptor names one (family_source: alias); an alias reaches a store's own name for the same content by one matching function.
Servable
Able to serve a request for a model, unlike a store that only holds it. A component such as a projector or a VAE is never servable on its own.
Up
Whether a hosted server's listing could be read. False, with a why reason, when its credential could not be applied or its wire kind is unsupported.
Hosted
A model server reached off this machine rather than resolved locally. Pick's hosted outcome names one answering instead of a local server; its entry names a base URL, a wire kind, and a credential name.
Held in
The storage inventory stores holding an object a family or alias matches, in store order; empty when no configured store reports the model.
Domain
The remote runtime name a listed server answers through, distinguishing a remote runtime's own servers from this machine's.
Instrument
The platform mechanism that measures a resource's holders, such as Windows' GPU process memory counters. A row above its declared threshold is measured; below it, or with no instrument for a resource, the row is claimed.
Engine
The program that loads model weights and answers calls, such as llama-server or ComfyUI. --engine names a path to one already installed on this machine; a provider module ships no engine, downloads none, and looks for none.
Lend
Writing a link into another application's engine directory so that engine serves an object already in a store, gated by abstraction.storage/lend@1. Never a move, a rename, or a deletion.
Ledger
The record of which lends are in force, oldest first; replaced in one rename, so a reader sees a whole ledger or the one before it. It says whether a lend is in force, not the engine's own list.
Object
A store's content, named the way the storage inventory names it: a store and an id, never a path.
Locator
An object's location a store reports when it published no manifest id; the ledger records the manifest id where the source published one, and the locator otherwise.
Inventory
The composed, read-only list of what objects a machine's stores hold, served by abstraction.storage/inventory@1 from designated abstraction.storage/inventory-source@1 providers, such as local-stores' own indexer.
Storage class
A retention promise: data, cache, tmp, or logs.
Retention
How long a class keeps an object once nothing holds it.
Max use
The most bytes a class may occupy.
Collector
The runtime's process that removes what a class no longer promises to keep.
Low free space
The collector's pressure trigger: 15% of the file system, capped at 4G.
Purgeable
A cache object marked for the platform cleaner.
No-backup
A folder's or object's attribute excluding it from backup.

Service lifecycle

From a requirement to a bound call

  1. Connect. A language facade selects the installed runtime for the current account and establishes the shared native IPC transport.
  2. Resolve. The client sends a capability, accepted services, guarantees, and placement to Resolver.Resolve.
  3. Authorize and select. The runtime identifies the caller, checks policy, and selects an eligible ready candidate.
  4. Bind. A generated client receives a service reference with one contract, endpoint, placement, and provider binding.
  5. Call. The generated client validates records and uses the shared transport. The OA service owns downstream provider connections and credentials.
  6. Continue. Accepted jobs remain associated with their original owner and binding. Observation, cancellation, and reconciliation use that association.

Go resolution shape

machine := facade.Discover()
logs, err := machine.ResolveLog(ctx, facade.Requirements{
    Scope: facade.ScopeLocal,
})
if err != nil { /* inspect the typed binding error */ }
logs.Write(record)

Left unset, Requirements.Scope resolves as any; set local or remote explicitly to restrict placement.

A later resolution may choose another eligible provider. An existing binding stays specific to the selected service. The facade contract defines resolution, trust, and binding behavior.

Authority

Identity, rights, and execution are separate facts

QuestionSource of the answerWhere it matters
Who connected?Native transport evidence captured by Identity, with proof attached to every attribute.Runtime selection, caller isolation, policy lookup, and audit.
May this caller act?Authorization.Decide or DecideFor under abstraction.rights/authorization@1.The service that owns the resource enforces the result before access or mutation.
Who executes the work?The service deployment and its configured provider.File access, network access, process lifetime, and provider credentials.
Is this the intended service?Runtime endpoint selection plus the transport's server-trust policy.Before sending requests or secrets.

Caller-supplied labels remain metadata. Provider names, model names, MCP client names, application titles, and context titles carry no identity authority. Credential values stay in the credential service and are applied to an exact target through Applier.Check and Applier.Apply.

Acceptance, observation, and recovery

Prepare identity first

Create the idempotency key before sending work. Equal duplicate submissions recover the original receipt.

Separate waiting from work

Canceling a transport wait ends that wait. Explicit work cancellation uses CancelWork with the original idempotency key.

ObserveWork · CancelWork

Reconnect to the original logical owner and call Reconcile. A new idempotency key would describe new work.

Opaque cursors belong to one provider instance and caller subject. A gap asks the caller to restart from a current snapshot or recover through a contract-specific path.

Applications and assistants

Directory metadata, activation, and tools have distinct roles

Register / RemoveAn authorized operator manages persistent manifests and activation recipes.
Announce / WithdrawA ready application creates and renews a leased instance with interface and context metadata.
ObserveA caller lists only manifests and live instances visible under its rights.
ActivateThe runtime starts a registered executable and waits for a fresh announcement from the eligible local session. Canceling the wait leaves the user application running.

These methods belong to abstraction.facade/applications@1. An interface entry describes an application-owned protocol such as comfy.presentation@1. Metadata does not invoke that protocol.

An application interaction adapter implements the protocol and preserves the selected instance, context, and revision through preview, apply, and readback. A stale revision refuses an outdated target. This adapter is specific to the application interface.

An MCP gateway maps a curated tool set onto OA clients and application adapters. The MCP gateway runs as its own verified integration subject and receives explicit rights. It exposes a selected tool set rather than generic forwarding to arbitrary MCP servers or application methods.

Failure and recovery

Read the typed result before retrying

ResultMeaningCaller response
forbiddenThe resolution boundary's own peer check: a different account, or a caller that cannot be verified.Run the program as the runtime's own account. No capability-specific rule is read yet.
not_permittedA verified caller's own rights rule refuses the action or resource, decided inside the call.Change the grant or choose an allowed action; see inference's Set up a host for a worked grant.
not_ready / unavailableThe required service or provider cannot serve the call now.Observe readiness or retry within the contract's bounds.
unmet_requirementsNo eligible candidate supplies every requested guarantee or placement.Install or configure a suitable provider, or revise the requirement explicitly.
unsupportedThe selected contract lacks the requested optional behavior.Use a supported method or resolve a contract that declares it.
invalidInput violates the contract's shape, bound, state, or identifier rules.Correct the request. Repeating the same bytes gives the same refusal.
stale / conflictA revision or compare-and-set base no longer names the current state.Read the current state and decide again.
gapRetained history cannot prove continuous delivery from the supplied cursor.Restart from a current snapshot or use the contract's recovery method.
uncertain / unknownThe caller lacks evidence of the effect or accepted work.Reconcile with the same idempotency key or read current state before acting.

Each contract owns its exact enum and recovery rule. The table is a navigation aid across recurring meanings.

Desktop and menu-bar Panel

The Panel, section by section

The Panel installs with the runtime and opens as a native window on Windows, macOS and Linux. Each of its sections links to its own anchor below: a "Learn more" link on Windows, a small "?" mark next to the heading on macOS and Linux, and a round "?" button for the current page as a whole. Every anchor names what the section does, the contract rule that decides it, and its command-line equivalent where one exists today.

Status

Service check

Rereads the resolved runtime's capability readiness, the call status also makes. Runtime selection and trust follow the rule status and rights both use: an explicit endpoint is never trusted as the installed runtime without its own registration proof.

The runtime is the shared background service every application on this account uses through OpenAbstractions. It runs work in the background, tracks the models and credentials an application may use, and holds the questions it is waiting for you to answer. A pending question appears under Questions and permissions; a download in progress appears under Work.

openabstractions status

Work

Work started from this Panel

Lists the jobs this Panel itself submitted, with each job's current state and display label. A job belongs to the program that submitted it (JOB-A1); this view shows only this Panel's own.

openabstractions jobs list

Work started by apps

Lists the jobs every application on this account submitted. Seeing them needs abstraction.job/inventory.read; canceling another app's job needs abstraction.job/acceptance.cancel (JOB-A1).

openabstractions jobs list --all, or jobs cancel --all <id> to cancel one

Download a file

Submits an HTTP(S) transfer to the runtime's job service by URL, digest and size, and recovers a saved request after a lost reply instead of resubmitting it. A dropped connection keeps its error, and the next attempt resumes from the last proven byte (DL-E1).

openabstractions download <url> --sha256 HEX --size BYTES

Questions and permissions

Questions

Shows questions applications have asked and lets you answer or dismiss them. The action catalogue for asking is closed to abstraction.asks/question.ask on the question's own resource (ASK-R1); dismissing removes the question without recording an answer.

No command-line equivalent yet.

Permissions

Allows or blocks one action for one account and application on one resource, at the policy revision shown. Every decision the runtime makes is checked again at call time under abstraction.rights/authorization@1; a Panel edit leaves a decision already made as it was.

Listing rules reads one revision at a time; list again to see a change made elsewhere. Applications are checked against these rules every time they act.

openabstractions rights list, or rights grant

Device

Holders

Shows who is using a limited resource on this device right now: the app, the account, how much, and whether it was measured or claimed. Verified rows are measured. A claimed row's amount is 0 unless the row is a lease, and then it is the grant the runtime wrote (RES-T3). A resource named card:<n> can report the same bytes as system memory on shared-memory hardware. A reader never sums two resources, or a verified row with a claimed one (RES-T5).

openabstractions resources

Downloads in progress

Shows background work every app on this account has started, the same account-wide list Work shows under Work started by apps; this view can't cancel it (JOB-A1).

openabstractions jobs list --all

Keeping this device awake

Shows apps and accounts keeping this device from sleeping, with how much, since when, and the lease id; when nothing reports this directly, an older account-scoped reading is shown instead and labeled as such. The wake lease is the one lease rights carries today (RES-A1).

openabstractions resources awake

Inference

Model servers and spend

Lists the model servers this device calls directly for model completions, separate from the gateway keys other apps use to reach it, with whether each is reachable and its spend today against its daily budget; adds or removes a model server. A hosted server's credential is applied to each outgoing request and never cached (INF-C1).

openabstractions inference server list, or inference server add / inference server remove

Inference gateway

Turns on the inference gateway, a local proxy other apps on this account can call, so an app that already speaks the OpenAI or Anthropic API reaches this device with no code changes. It listens only on 127.0.0.1, stays off by default, and stays set after a restart. Changing it needs the rule inference server manage (abstraction.inference/host.manage).

openabstractions inference gateway on --address 127.0.0.1:PORT, or inference gateway off

Gateway keys

Issues or revokes a gateway key, which lets one other app reach this device through the inference gateway; the key is shown once and this Panel never stores it. A key alone grants nothing: the app still needs inference complete (abstraction.inference/complete) on a model server and permission to apply a hosted server's credential.

openabstractions inference key issue --for PATH, or inference key revoke

Audit

Lists every inference decision from direct calls and the inference gateway, with how strongly each caller's identity was verified.

openabstractions inference audit

Providers

Model servers

Lists every model server the runtime can reach and which app or file registered each one: something you configured, an app's own record, a built-in default, or another trusted runtime.

openabstractions inference server list

Registered providers

Lists every registered provider and its role (a managed process, a model server, or a remote runtime) with its activation, services, endpoint and readiness. Every registration is providers/<name>.json in the runtime's own state (FAC-R1).

openabstractions provider list, or provider add / provider remove

Remote runtimes

Lists model servers reported by another trusted runtime in its own domain; their credentials stay on that runtime and are never copied here. Trusting a remote runtime's report follows the same registration rule as a local one (FAC-R1).

No command-line equivalent yet.

Credentials

Saved credentials

Lists every credential registered on this account: its name, kind, status, targets, consumers and where it's used. The secret itself is typed in once and never shown, logged or sent back.

openabstractions credentials list

Add credential

Registers a name that isn't already in use, scoped to the hosts it may be sent to and the apps allowed to apply it. The credential manager binds the caller the same way for every write (CRED-H1).

openabstractions credentials add <name> --target HOST --for CONSUMER

Rotate

Replaces the secret and expiry for a name you've already listed, at the revision the list showed.

openabstractions credentials rotate <name>

Revoke

Deletes the secret right away and keeps a record that it existed, at the revision you've already listed.

openabstractions credentials revoke <name>

App access

Sets whether one app on one account can use a credential, through the rule credentials apply (abstraction.credentials/apply) on that credential; it's the same rule editor as Questions and permissions. Listing and editing it needs this Panel to hold credentials manage (abstraction.credentials/holder.manage) and credentials list (abstraction.credentials/holder.read) (CRED-A2).

openabstractions credentials allow <name> --program PATH, or add --deny

Settings, logging, identity and explore

Settings

Reads and writes your settings and watches them for later changes. Each value says where it came from: for you, for this device, or for this run. A value's source follows the location order process over user over machine (CFG-R1); an environment variable overrides for that process only, and an empty one is no override (CFG-W3).

Disabled download delegates switches the nas and bits delegates off on this device. The two job directory rows are deprecated. Watching settings for changes does not touch what you are editing. If settings change while you are editing, save your draft first, then read again. Pause, resume, download destinations and host refusal files are set from the openabstractions command line for now.

No command-line equivalent yet.

Logging

Reads the runtime's retained log history, filtered by program and level, and can follow new records as they arrive. Each record's hop 0 is the process that wrote it; later hops are what each next service could verify about that write (LOG-I1).

A claim an application makes about itself is unverified. A stamp this runtime's logging service adds itself is verified.

No command-line equivalent yet.

Identity

Shows which runtime this device selected, how it bound this Panel's own connection, and what this platform can prove about a caller. A bound attribute is proven by native transport evidence, or left unbound where the platform cannot prove it (ID-B1).

No command-line equivalent yet.

Explore

Calls a capability as this Panel and shows the result beside the rights rule that allowed or blocked it, so a grant or a revoke can be tried again without leaving the page. This is the same call probe makes, including a probe marked writes, which asks before it runs.

Grant or revoke the deciding rule for an application directly from a result, then try the call again. This Panel can only act as itself here; to test another application, run a copy of openabstractions named openabstractions-probe under that application's own path.

openabstractions probe <capability> [action]

Compare the APIs

The same event in your language

These examples write a structured log event through an already resolved client. Select a language to compare its native API. The calling application handles any returned error or exception.

import (
    "context"
    "log/slog"
    logging "github.com/openabstractions/abstraction-logging/go/client"
)

func recordStart(ctx context.Context, events *logging.Client) error {
    return events.LogContext(ctx, int64(slog.LevelInfo), "worker started",
        map[string]string{"component": "worker"})
}
from datetime import datetime, timezone
from abstraction.logging import Record, Sink

def record_start(events: Sink) -> None:
    events.write(Record(
        schema=1,
        time=datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%S.%fZ"),
        level=0,
        msg="worker started",
        attrs={"component": "worker"},
    ))
#include <abstraction/logging/client.hpp>

void record_start(const abstraction::logging::Logger& events) {
    events.log(0, "worker started", {{"component", "worker"}});
}

Supply the current UTC timestamp in RFC 3339 format.

use abstraction_logging_api::{Record, Sink};

fn record_start<S: Sink>(events: &S, timestamp: String) -> Result<(), S::Error> {
    events.write(Record {
        schema: 1,
        time: timestamp,
        level: 0,
        msg: "worker started".into(),
        attrs: [("component".into(), "worker".into())].into(),
        ..Default::default()
    })
}
import {newRecord} from '@openabstractions/logging';

/** @param {import('@openabstractions/logging').SinkClient} events */
async function recordStart(events) {
    const record = newRecord();
    record.schema = 1n;
    record.time = new Date().toISOString();
    record.level = 0n;
    record.msg = "worker started";
    record.attrs = {component: "worker"};
    await events.write(record);
}
