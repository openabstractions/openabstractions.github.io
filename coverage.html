What a cell means

cellmeans
PASSthe recorded checks passed within their stated scope and exceptions
FAILevidence exists and a rule broke
UNPROVENcould not be checked here — a toolchain absent, a platform absent, a harness skipped, or a result nobody records
ABSENTchecked, and the thing is confirmed not there — a language this project's own inventory claims and the tree does not have
—no implementation/client found for this layer and language; absence does not establish intent

UNPROVEN and — are not the same thing and must never be read as one. A missing implementation is an adoption gap. An implementation that exists and nothing tests is written UNPROVEN so it looks like one.

Why each cell reads as it does

The reason is the point of the table. gate is a cell the project's own gate runs on every change and no recorded run wrote down; skipped is a cell the last recorded run could not judge; unreached is a cell nothing runs at all. All three are UNPROVEN and they are very different gaps.

Where the evidence comes from

Six cross-language harnesses and one public suite. Five of the six say which language a result belongs to, and two of them leave a committed transcript naming the commit they judged. The rest of the grid rests on the gate itself, which builds and tests most of these cells on every run: scripts/check.sh --record writes what it reached into GATE.txt, one line per cell. A cell still reads gate where no recorded run has judged it.

harnessaskssays which language?leaves a committed transcript?
behaviour-conformance.shdo the implementations do the same thingyes — every scenario line names the languages that agreed, and an absent one is named tooyes, BEHAVIOUR1.txt
spec-conformance.shdo they read a download spec the same wayyes — it prints its roster and names any implementation that did not runno
verdict-conformance.shdo they refuse the same documentsyes — a divergence names the implementations on each sideno
conformance.shcan each language finish a job another startedyes — every step names the implementation that took itCONFORM1.txt, with no header naming the tree it measured
obtain-conformance.shcan a stranger get each implementation through its own front dooryes — one line per doorno
identity-conformance.shdo Go and Python group model names the same wayyes — it names the one that disagreesno
conformance/run.shdoes one implementation keep the rules on the contract pagesno — it judges one driver per run and the driver is the caller's choiceno

The grid also reads the tree itself: which <layer>/<language>/ directories exist, which Go modules the workspace lists, which C++ directories the top-level build adds, which Python suites the gate names, and how many test files each cell carries.

Nothing here carries an API stability promise. UNPROVEN is written wherever a platform has not been reached.
