What a cell means

cellmeans
PASSthe recorded checks passed within their stated scope and exceptions
FAILevidence exists and a rule broke

Where the evidence comes from

Four harnesses and one public suite. Each harness says which language a result belongs to, and one of them leaves a committed transcript naming the commit it judged. The rest of the grid rests on the gate itself, which builds and tests most of these cells on every run: scripts/check.sh --record writes what it reached into GATE.txt, one line per cell. A cell still reads gate where no recorded run has judged it.

harnessaskssays which language?leaves a committed transcript?
behaviour-conformance.shdoes the Go implementation do what the contract pages stateyes — every scenario line names the languages that agreed, and an absent one is named tooyes, BEHAVIOUR1.txt
spec-conformance.shdoes a reader read a download spec as the contract statesyes — it prints its roster and names any implementation that did not runno
obtain-conformance.shcan a stranger get the Go implementation through its own front dooryes — one line per doorno
identity-conformance.shdo Go and Python group model names the same wayyes — it names the one that disagreesno
conformance/run.shdoes one implementation keep the rules on the contract pagesno — it judges one driver per run and the driver is the caller's choiceno

The grid also reads the tree itself: which <layer>/<language>/ directories exist, which Go modules the workspace lists, which C++ directories the top-level build adds, which Python suites the gate names, and how many test files each cell carries.

Nothing here carries an API stability promise. UNPROVEN is written wherever a platform has not been reached.
