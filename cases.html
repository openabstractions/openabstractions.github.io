What applications gain from the service boundary

Each case starts with a task a person recognizes and one capability that can span an operating-system facility, a local program, or a remote service. OA checks permission and preserves the capability's meaning across those implementations.

Find an application integration · See how AI applications share models and memory. Measurements below describe dated development experiments; current qualification is recorded in coverage.

An image editor keeps rendering while a chat engine gives the card back

The task

ComfyUI needs more of the graphics card than is free. LM Studio is holding a model on the same card and neither program knows the other exists.

OA's role

ComfyUI asks the resource service for room on the graphics card. The service asks LM Studio to yield through LM Studio's own unload endpoint, then grants a lease once the bytes are free.

On the owner's machine, a render needing 106 GiB of a 124 GiB pool asked while LM Studio held one model. LM Studio gave back 21.4 GB of graphics memory (yielded, in OA's word) in 7.3 s, the reservation (lease) was granted, and the render finished in about 31 s and saved an image. A deny rule written for the same holder changed the identical ask into a refusal read from ComfyUI's own queue in about 150 ms, with LM Studio's model still loaded and nothing allocated.

Measured: 132,766,306,304 bytes (123.65 GiB) pool; 113,952,739,328 bytes (106.13 GiB) reserve; 21,446,795,264 bytes yielded in 7.305 s; render in 30.98 s; refusal in 146 ms. research/resources/COMFY-CARD-2026-09-22.md, sections 1 and 3.

LM Studio unloads its model, then ComfyUI loads its own weights into the freed memory. The resource repository is preparing its first tagged release.

A coding assistant reaches every local model through one runtime

The task

An OpenCode user with a local model wants to chat with it through OA, with nothing to type into OpenCode's own configuration.

OA's role

openabstractions opencode configure reads the router's servable chat families through the runtime and writes OpenCode's provider block for them.

Proven under a real Bun with installed selection on Windows: conversation, tool calls, provider substitution, attribution, and a refusal returned before any provider I/O runs.

Not yet proven: an end-to-end run against a live Ollama, LM Studio or Lemonade server through the runtime. A host is declared by hand today; the router's live survey of installed local servers has no recorded run through the runtime yet.

A model file downloaded once is served by another engine

The task

A model file (GGUF) sits in the Jan app's model folder (the jan store) on this machine. LM Studio never downloaded it and cannot see it.

OA's role

The model bridge resolves the file through the storage inventory and lends it into LM Studio's own models folder by link, once the operator permits lending to that engine.

On 2026-09-22 a 46 MB GGUF from the jan store was hard-linked into LM Studio's models folder in 6.3 seconds end to end: the first lend attempt was refused not_permitted, the lend after the rule placed one hard link, and LM Studio listed the file under its own derived name inside a 30-second window. unlend removed the link and its directories again; the source file in the jan store never moved.

Measured: 45,949,216 bytes in 6.3 s end to end. abstraction-provider-modelbridge/README.md, "Measured".

Model bridge source and recovery guide. Its first tagged release is in preparation.

A coding assistant can change model providers

The task

A coding assistant streams an answer from a requested model. The operator may run that model locally today and through a remote host tomorrow.

OA's role

The assistant requests a model and execution placement. OA checks its rights, selects an eligible declared host, and mediates a connection pinned to that provider declaration.

The same inference family also carries embeddings, speech synthesis, transcription, live sessions, and image generation. Each modality has a defined request and a streamed or final result. Current modality and language results live in coverage.

An image editor can return to the same download

The task

A node-based image editor needs a multi-gigabyte model. The user closes the editor while the transfer is active and later returns.

OA's role

The editor submits one retained job. OA owns progress and settlement. The editor saves the returned operation reference and observes the same accepted work after restart.

The ComfyUI source adopter supplies this integration path. Storage lookup can reuse matching content before the editor requests another transfer.

An assistant can open an app and propose a specific action

The task

An assistant needs an image editor, then wants to preview a sampling-step change in the document the user is viewing.

OA's role

With permission, OA activates an operator-registered app and waits for that app to report readiness from the same signed-in session. The app reports its current document and revision.

The OA Model Context Protocol (MCP) gateway lists visible applications under its own verified program identity. Activation uses the facade API. A separate image-editor adapter owns the preview, apply, and readback tools. A proposal carries the exact app instance, document, and revision; a changed document produces a stale result. Presentation stays inside the requesting task and application tool surface.

This is a scoped development composition with current live evidence. OA defines no universal application UI protocol. Coverage records the tested source and limits.

An operator can see and control the boundary

Rights and providers

The OA Panel shows which programs may do what, which providers and model hosts are registered, whether they are ready, and which saved credential names exist. Revoking permission changes later decisions.

Configuration and evidence

The Panel edits revisioned user settings, follows effective configuration, reads retained logs, and shows caller identity and provider diagnostics.

Limits remain part of the product

  • Provider registration, application visibility, activation, invocation, and effect authority are separate grants.
  • A lost submission reply produces an uncertain state and reconciliation with the original owner.
  • Local and remote execution placement remains explicit through provider selection and forwarding.
  • Current feature evidence uses controlled integrations and actual local applications. Release packaging and broader provider interoperability require their own evidence.
