Applications and integrations

Where you can try OA

Connect OpenCode to OA inference, use OA downloads in ComfyUI, or expose OA tools through MCP. These OA-maintained integrations are being qualified for 0.3.0. Setup and evidence limits are listed with each integration.

OpenCode: one model provider for the runtime's chat models

Use local or explicitly permitted hosted inference while OA manages routing, named credentials, streaming and cancellation. Revoking the OpenCode program's permission prevents subsequent provider requests.

Setup: install the development OA provider for OpenCode, run OA with an eligible model server, then use openabstractions opencode configure. The provider's README describes source and package setup; npm publication remains pending.

Evidence: the controlled Windows Bun integration covers chat, tool calls, cancellation, rights refusal and provider substitution. Live end-to-end runs with each supported engine remain separate acceptance work.

ComfyUI: recover model downloads and coordinate memory

The download node can return to work owned by OA after the editor restarts. Storage lookup can reuse known content. The resource experiment lets an image workflow request room from a supported model holder before it starts rendering.

Setup: the OA download node and runtime supply the download path. Resource coordination and the presentation adapter are separate development integrations with their own setup and permissions.

Evidence: the download adopter has executable recovery tests. A local ComfyUI/LM Studio experiment exercised memory yield and denial. The presentation adapter demonstrates a proposed parameter change, revision check, apply and readback.

Ollama, LM Studio and Lemonade: model hosts behind the runtime

OA connects to these engines through their supported server interfaces. Applications call OA's inference API; the runtime selects an eligible registered host. An engine's supported models, modalities and unload operations determine what OA can offer through it.

Setup: install the engine, make a compatible model available and register its server with OA. The model bridge can lend supported local files to LM Studio, Lemonade or ComfyUI. The engine and file format must support that placement.

Evidence: protocol tests cover the adapters. Local experiments record LM Studio memory release and model-file lending. The full live engine matrix is still being qualified for 0.3.0.

MCP clients: use OA through tools

An assistant with MCP support can use the OA gateway's tools without adding OA libraries to its application. The local gateway process connects to the runtime, and OA applies the grants assigned to that gateway program.

Setup: configure the OA MCP gateway in the assistant and grant the actions it needs. An application's presence in the registry and permission to invoke its tools are separate decisions.
