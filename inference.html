Three cooperating abstractions

Model lookup, routing, and inference answer different questions

What is this model?

Model

Resolves a portable registry and repository reference into a manifest. The manifest can describe files, revisions, and how content is obtained.

abstraction.model/resolver@1Model catalogue entry

Where can it run?

Router

Lists eligible models and hosts, then picks a host that matches the model, modality, guarantees, and placement.

abstraction.router/router@1Router schema

How does this call run?

Inference

Checks admission, rights, content, capacity, credentials, and budget. It owns the upstream request and returns the modality result.

abstraction.inference/*@1Inference schema

An application can use Model without running inference, and it can request inference with a model name already known to its workflow. The runtime composes the three when a call needs all of them.

Execution boundary

The application stays on local IPC while execution placement changes

local

Resident host

A model engine on the receiving machine performs the call. local-only@1 constrains selection to this placement.

remote

Remote runtime

The local OA service relays to a declared, mutually trusted runtime. The selected binding records remote execution.

hosted

Hosted API

hosted-allowed@1 lets the router consider a configured hosted provider after eligible local hosts.

Before bytes leave the service

  • Validate request shape, bounds, and required features.
  • Select a host that advertises the requested modality and model.
  • Decide abstraction.inference/complete for the caller on host:<name>.
  • Resolve content digests under the original caller's storage rights.
  • Check the credential ceiling and operation capacity.
  • Apply a hosted credential for the exact profile and target.

Vendor keys, base URLs, and request headers remain inside the service. Hosted credentials are named in requests and applied inside the receiving service. A remote runtime resolves digest references from its own authorized content store. Digest transfer between stores remains future work.

Future resolutions see the new configuration

An authorized operator can list, add, and remove hosts, inspect profile readiness and current credential spend, issue local gateway keys, and read the inference audit.

Removing a host leaves already admitted operations running to their defined end. Provider declaration and generation pinning prevent an existing binding from silently becoming a different provider.

Each host advertises specific profiles. A chat-only provider remains chat-only.

Developer API

Resolve a typed client, then use the modality lifecycle

Go · chat client shape
machine := facade.Discover()
chat, err := machine.ResolveInference(ctx, facade.Requirements{
    Scope: facade.ScopeLocal,
})

reply, err := chat.Complete(ctx, inference.Request{
    Model: model,
    Messages: messages,
    Guarantees: []inference.RequestGuarantee{inference.RequestGuaranteeLocalOnly},
})

The facade currently exposes direct resolvers for chat, embeddings, and inference operator control. Generated modality clients bind transcription, speech, live, and image service endpoints.
